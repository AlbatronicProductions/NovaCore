# Hierarchical celestial reference frames

Milestone 4 keeps all `ReferenceFrame` semantics in managed `NovaCore.Core.ReferenceFrames` and evaluates them from explicit caller-supplied state. `ReferenceFrameDefinition` contains only ID, parent ID, kind, and diagnostic name. Snapshot-time transforms, origin velocities, angular velocities, and inertial state are stored separately in `EvaluatedReferenceFrame`.

The hierarchy is `ECL → ORB` and `ECL → CCE → CCI → CCF`. ECL is the sole inertial root. ORB receives an explicitly supplied ECL origin and velocity; this milestone derives only its orientation as `Rz(LAN) * Rx(inclination) * Rz(argument of periapsis)`. CCF receives an explicit rotation angle and angular rate, never wall-clock time.

All values are doubles and all transforms are rigid local-to-parent transforms: `pParent = translation + rotation(pLocal)`. Velocity transport includes `omega × r`. `ReferenceFrameSnapshot` validates IDs, parents, cycles, root validity, finite values, and normalized quaternions, then caches local-to-root transforms and root kinematics. `FramePosition` resolves to root/ECL `UniversePosition` before entering Graphics. The Free camera resolves through this same snapshot path in `CameraRenderSnapshotBuilder`.

Camera terminology is strict. **CCI / Root Inertial** is the celestial translation/orientation reference used by the default camera orientation. **CCF / Body Fixed** is the rotating geography frame used by materials, terrain, surface anchors, and body-fixed orientation. **Local Surface** is reserved for the Phase B east/north/up camera contract. **Camera Relative** is renderer transport obtained only after FP64 root-space camera subtraction. A CCF focus position does not imply a CCF camera orientation: a body-fixed anchor may move in root space while the camera orientation remains CCI/root-inertial.

Milestone 6C-1 consolidates the allocation-free position, direction, orientation, transform-composition, and rotating-frame velocity equations in an internal reference-frame math boundary. It owns no clock, timeline, state, snapshot publication, or renderer behavior; it exists only to keep the deterministic double-precision equations shared by snapshot construction and contextual conversion consistent for later simulation work.

Milestone 6C-2 adds `ReferenceFrameGraph`, an immutable structural topology separate from evaluated frame snapshots. It stores only frame identity metadata and insertion-validated parent-child relationships. Roots, children, strict ancestry, and depth-first traversal are exposed through value-type views over frozen arrays, so traversal performs no managed allocation and follows deterministic insertion-derived order. The graph does not resolve transforms or positions and has no simulation-time, state, propagation, or rendering ownership.

Milestone 6C-3 adds internal read-only graph path queries. Lowest-common-ancestor lookup and root-to-node or node-to-node paths use caller-provided spans and return controlled statuses for unknown frames, unrelated roots, and insufficient buffer capacity. Paths contain only `ReferenceFrameId` topology order; no transform is evaluated or composed.

Milestone 6D-1 layers internal transform resolution over immutable topology. `ReferenceFrameTransformSet` stores separately supplied, immutable local-to-parent `EvaluatedReferenceFrame` values aligned to one graph; graph nodes remain topology-only. The resolver uses LCA and caller-provided path buffers, composes source and target local-to-root kinematics with the shared pure math helpers, then returns source pose, origin velocity, and angular velocity in target coordinates. Position, direction, orientation, and velocity conversion use that result; velocity follows `vTarget = vOrigin + R(vLocal) + omega × R(rLocal)`. No propagation, acceleration, time evaluation, snapshot publication, or rendering integration is present.

Milestone 6D-2 provides `samples/NovaCore.ReferenceFrameFixture`, a managed terminal fixture run with `dotnet run --project samples/NovaCore.ReferenceFrameFixture -c Debug`. It constructs static `ECL Star → CCE Planet → CCI Moon → CCF TestVessel` topology and separate evaluated transforms, verifies root and frame-to-frame conversion, direction/orientation conversion, and the rotating-frame velocity contribution. Its fixed query order hashes raw resolved numeric values and checks that 100,000 warmed resolutions allocate zero managed bytes. It is not a solar-system simulator: it has no propagation, authoritative time binding, `SimulationSnapshot`, rendering, or gameplay.

Milestone 7D adds a narrow celestial extraction pass in `NovaCore.Simulation.Celestial.ReferenceFrames`. At one requested exact instant, it reads immutable authoritative celestial trajectories and fills caller-provided `ReferenceFrameEvaluation` storage for a matching immutable graph. The celestial root maps to the graph root with identity transform and zero velocity. Each child trajectory supplies its local translation and origin velocity in the declared primary frame; orientation is identity and angular velocity is zero. The evaluator validates one-to-one frame mapping and matching parent chains before extraction. It does not evaluate trajectories inside the transform resolver, mutate state, construct graphics data, or publish a transform set.
