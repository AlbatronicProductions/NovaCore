# Planetary scientific-data ingestion

## Authority boundary

Planetary scientific rasters are offline inputs, not runtime authorities.
Source manifests retain publisher, product/version, licensing, CRS/datum,
bounds, resolution, sizes, hashes, retrieval dates, nodata handling, and every
transformation. Runtime code opens only checked NovaCore products; it never
downloads, reprojects, or recompresses scientific imagery.

## Production terrain-v5 pipeline

Earth production data is generated by `tools/earth_data`:

1. `build_elevation_oracle.py` converts the lawful ETOPO input into the checked
   topology-neutral 8192 × 4096 R16 CPU oracle used for clearance and parity.
2. `build_cube_surface_pack.py` samples lawful albedo, elevation, and cloud
   sources through the relaxed cube-sphere projection.
3. Every record is identified by
   `body / terrain-version / face / level / x / y`.
4. Canonical spherical gutters cross cube-face boundaries through the same
   projection as geometry; equirectangular U/V pages are not runtime owners.
5. Albedo, elevation, classification, and cloud payloads for one spherical
   patch are published transactionally. A complete parent remains authoritative
   until its complete child quartet is resident.
6. The canonical right-handed body geography uses +Y north, +X at longitude
   zero, and -Z at +90 degrees east; source U increases with east longitude.
7. `build_local_terrain_pack.py` emits the optional `earth-local-v2` NCCUBE2
   level-12 refinement payload using the same terrain-v5 geography and lawful
   albedo/elevation sources. It refines the global owner; it is not an
   independently visible regional page system.

The canonical initial `earth_surface_v5.nccube` hierarchy contains all 126 L0–L2
patches and is intentionally shallow. Near-planet density comes from the four
persistent production Eyeball tiers, which sample the same terrain-v5 patch
authority. Its 61,484,224-byte identity lives in the tracked distribution
manifest while generated bytes publish to the ignored content-addressed cache,
not Git or build outputs. The runtime cache has bounded background reads,
pending work, uploads, and resident payloads. See
[`terrain-assets.md`](terrain-assets.md) for explicit build/fetch/verify,
streaming SHA-256, atomic publication, and fresh-clone behavior.

## Retired regional-page proof

11B-3B previously proved bounded ingestion of official USGS/USDA NAIP and USGS
3DEP exports around Mount St. Helens. The exact lawful sources, queries, CRS,
NAVD 88 vertical datum, sizes, hashes, terms, and quality measurements remain
in `assets/earth/source/regional/mount_st_helens/source.json`.

That proof emitted independent equirectangular `.ncvreg` pages with separate
fallback and promotion. 4C retires its builder, runtime pack, index, lookup,
descriptor, and residency paths because those contracts conflict with coherent
terrain-v5 spherical-patch ownership. The source data and provenance are kept
for a future cube-patch-aligned regional ingestion tool; the retired pack is not
a production or migration dependency.

The historical proof covered 343 km² at approximately ten-metre source spacing
and documented why global distribution at that density is impractical. Those
measurements remain provenance, not a proposal to restore the old page model.
