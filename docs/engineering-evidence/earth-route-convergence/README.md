## Recovering an engineering conclusion

1. Read the current repository report and the original report/READY/log entries in the named ZIP. Preserve the distinction between a historical failure and final acceptance.
2. Use retained-manifest.json to locate exact original members and their SHA-256. ZIP member paths retain the original repository-relative build paths. Metadata includes camera/pupil/publication identities and numerical summaries; retired-file-manifest.json.gz records every removed original and its hash/category.
3. For a new reproduction, use permanent route, physical/residency, support, visibility and coordinate regressions first. Restore only needed diagnostic tooling from a ZIP into a new isolated build directory. Archived source/configuration and CMake toolchain records explain the historical instrumentation. Old absolute paths and retired APIs may require deliberate adaptation.
4. Do not run archived implementation/mutation scripts against the current repository. They document how historical instrumented copies were made; Git/current source remains implementation authority.
5. Old frame-analysis scripts may require a fresh capture. No promise is made of bit-identical historical executables, exact camera-time timing or every historical frame. The preserved report/identity/visual/numerical evidence is the permanent record.

Permanent regression responsibilities retained in source: EarthRouteConvergenceTests, RegionalPhysicalResidencyTests and its live generated-output recipe, FacilitySupportTests, FloridaFoundationSeatingTests, FacilityLightingTests, native regional/visibility/material-coordinate tests and their shaders, canonical physical authority and P3/publication checks.
