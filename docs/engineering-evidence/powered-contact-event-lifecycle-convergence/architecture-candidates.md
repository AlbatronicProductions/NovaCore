# Three candidates, complexity and one bounded next ticket

## A — Current exact contact-piece model

Exact event → separate exact-duration constrained powered piece → producing-basis/duration/load/D/cache preparation → fixed coupled sweeps → remaining coast → endpoint.

Strength: explicit chronology, existing substantial ordinary/tiny physical evidence, exact resource authority, known failure evidence. Weakness: event algebra determines solver duration/cache transitions even below representable backend time; finite-sweep cancellation makes representation-specific paired sensitivity difficult. The current physical equations themselves depend on partition; complexity alone is not a rejection. Keep frozen and unqualified; do not erase its useful outcomes or successful witnesses.

## B — Literal current KSA lifecycle with NovaCore owner boundaries

Current5438 command/module preparation → prepared outer-substep wrench → ordinary retained float contact slices → staged resource drain/mass refresh → ready/apply. Pair-clearance horizons may select outer substep endpoints; this is not once per display frame and not a proved exact fuel-empty partition.

Source-proven ordinary lifecycle, familiar retained manifold ownership and bounded solver slices. However installed liquid shortage is positive availability then clamped drain; commanded-time scaling is not exact resource-event integration. Source mass cadence is not a continuous changing-mass proof. Its sequential game apply is not NovaCore atomic canonical publication. Copying those facts loses protected outcomes.

B is not selected as a correctness mechanism. Adapting it enough to retain chronological constrained event effects, variable-mass response and exact atomic authority becomes physically distinct candidate C rather than a minimal port. KSA precedent does not settle NovaCore exact exhaustion.

## C — Chronological exact-event consequences inside an ordinary contact numerical lifecycle

Exact NovaCore command/resource authority → admitted chronological constrained event response with mass/force/temporal moments → ordinary retained-contact numerical advancement/continuation → single prepared canonical endpoint/resource/engine publication.

The [derivation](exact-event-physical-requirements.md) proves mathematical existence for fixed independent constraints and an unchanged admitted mode, including a fixed linear compliant model. It does not prove an arbitrary endpoint impulse injection into BEPU. The response must be inside the physical operator, not tacked onto its result.

Prefer C as the architecture direction for one feasibility proof, not an implemented or qualified replacement. It preserves event semantics without assuming dt=h is a solver requirement. It also makes the hardest missing obligation explicit: a bounded contact operator and retained-world installation/continuation must preserve chronological reaction, variable mass, friction/work and mode transitions. No general backend bridge is claimed. Refusal in the first narrow proof does not count as satisfying eventual “interior exhaustion does not abort” for arbitrary supported contact.

## Why C wins the next proof

Exact segmentation source does not call a solver. The analytic constrained kernel gives a legitimate chronological realization without infinitesimal dt, while counterexamples positively rule out cheap but wrong impulse/averaging shortcuts. B's actual shortage/mass/application behavior cannot establish NovaCore outcomes. A remains a viable experimental reference, but neither its paired-column contract nor its exact-piece partition is proven necessary.

The choice is conditional on physical feasibility and complexity. If C needs an unbounded mode solver, reproduces all A machinery without useful simplification, hides approximation, or cannot preserve ordinary contact outcomes, stop and reconsider A or another explicitly authorized scope. Do not approve C solely because it sounds simpler.

Use the departure and friction-work counterexamples as negative admission/shortcut controls. Unsupported regime changes must refuse before writes; they are not “passing powered departure.” Include current zero-engine contact compatibility and source/ownership/future-cache applicability as requirements.

Specify the physical/error/rounding contract and outward regime bounds before implementation. Compare both velocity and position/rotation consequences, reaction, work/friction, mass chronology and exact ledger order.
