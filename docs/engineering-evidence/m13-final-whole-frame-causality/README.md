## Implementation and portable fallback

The six roles are prepared physical storage, regional physical staging, immutable topology lattice, immutable topology indices, visibility output and compacted index output. Current/incoming/spare lifetime, capacity growth, resource counts, mapping, descriptors, barriers, fences and publication remain unchanged. Counters, indirect/control blocks, regional catalogs and material upload staging keep their existing path.

Five populated fixed-L17 allocations total 96,846,304 bytes; the regional staging role is additionally used when needed. The private regional ledger has 27 allocation events totaling 388,836,032 bytes. These figures are not peak simultaneous residency or extra allocations. Placement changes eligible heap ownership, not total requested capacity.

`MappedBufferMemory.h` filters `memoryTypeBits` and required `HOST_VISIBLE|HOST_COHERENT` before preference. If no local compatible type exists, the original selection remains usable. Preferred allocation/mapping capacity failures may retry the original compatible type after cleanup; device loss, binding failure and unrelated failures remain observable. The same type is never retried on UMA. Tentative handles become live only after successful map/bind. Fourteen permanent native policy cases cover selection, compatibility, coherent requirements, fallback/error and single-attempt behavior.

The fallback preserves functionality, not the measured performance gain on every device or under all memory pressure. Details and source ownership are in [implementation-decision.md](implementation-decision.md).
