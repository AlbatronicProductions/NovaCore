The verifier located 95–99% of retained B tail duration in the preparation
timestamp bracket. That does not identify JIT, scheduler or GC cause. All retained
top-ten B tails occur by sample index 325; this does not say all earlier samples
are slow or all later samples are fast. C is later in process history plus its own

One mechanical reporting-only compiler error preceded all timing processes:
Timing.cs used long maxPoolBytes with an unsigned pool total, causing CS0121 at
Math.Max (decimal/float overload ambiguity). Changing that reporting variable to
ulong resolved compilation. No mapper/timing boundary changed, no failed timing
process occurred, and no runtime run was retried. Allocation/native builds and
the corrected timing build passed with zero warnings/errors. No full-solution
build or permanent test campaign was needed/authorized here.

A separate report-generation PowerShell parse initially rejected the retained
JSON's distinct h/H keys; -AsHashtable preserved case and permitted read-only
comparison. This was not an FP32 or runtime failure; no executable was rerun.
