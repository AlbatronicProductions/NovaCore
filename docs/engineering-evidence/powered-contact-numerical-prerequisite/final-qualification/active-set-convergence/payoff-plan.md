# Local Release payoff plan, before timing

Three fresh Release processes. Each interleaves D+8, D+12 and no-D+12 with rotating arm
order, 128 warm operations per arm then 1,024 measured operations per arm. Each call starts
from the same immutable accepted actual baseline tuple; no preceding proposal is installed.
All three arms use the same full operator path and exact coast equations. Only D inclusion
and sweep count differ. No resetting tangent, oracle, cold cache or predictor is timed.

Build a diagnostic timing variant with observation calls removed, retaining identical
numerical operations and switches. Entry checks, transport, exact-duration transformation,
load correction, D when enabled, current feasibility, sweeps and endpoint/proposal export
are inside the timer. File loading, allocation of owners/sample arrays, output, sorting and
correctness comparisons are outside. No new GC boundary or runtime/tiering setting.

Require Ready on every measured call, unchanged accepted owner and final timed output equal
to the independently checked diagnostic output. Require Release D+12 and no-D+12 pass frozen
physical bars; D+8 remains the known failing cost baseline. Stop on unexpected correctness or
identity failure. Record median/P95/P99/max and five worst sample indices for every process
and arm. No timing ceiling is invented; this is local class payoff, not integrated acceptance.

Report full measured tails without trimming or retry. Historical 3.4us/3.9us numbers are not
reused: their workload boundary differs from this complete exact-duration retained operator.
No conditional-transition policy is measured unless a pre-solve classifier is independently
justified; current-reference labels are unavailable to runtime admission.
