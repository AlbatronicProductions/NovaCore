## 1. One physical interval owner

Use **SimulationTransactionEngine**, already the command/resource/physical publication owner. Factor its existing powered preparation/service responsibility into one engine-owned interval coordinator with exactly one selected consumer: existing M15.0 free-flight or retained contact. Preserve M15.0's public/internal capability and behavior through the same free-flight route. Do not create a second actual-actuator/resource store or another spacecraft evolution object.

The engine owns one outstanding powered interval for this bounded spacecraft. A typed consumer discriminator plus genuine bound capability is selected before preparing any numerical result. A live retained-contact binding excludes the free-flight consumer; an ordinary pending endpoint excludes preparing another interval. Selecting a consumer is not inferred from a render flag, numerical position equality or a contact-count guess made by a callback.

The common immutable prepared value contains: spacecraft/root/body model identity; source SpacecraftPhysicalSource and bits; StateRevision/TimelineRevision; command authority/lease/revision/consumed sequence/closed-boundary identity; immutable engine definition/version and genuine preparation proposal; resource definition/version/revision and genuine resource proposal; original schedule T0, boundary index and exact start/target; exact segmentation; selected consumer; and, for contact, engine/world seal, generation, acknowledged frontier, episode/configuration/frame identity. Seals/capabilities remain private execution data, never canonical history.

The common value does **not** choose a universal mass integrator or compute an independent physical trajectory. Free flight consumes the exact segments through its current changing-mass evaluator. Contact consumes their bounded ordinary-step projection using source-held numerical properties. Both return one proposed endpoint to the same canonical writer.

## 2. Preparation and command lifecycle

Reuse the current sequence in ServicePoweredFlightDebt: admit host credit separately; check source/end/event/debt/history/revision; commit eligible command events at the source boundary; close that boundary; prepare single-engine demand; prepare exact resource segmentation; select/evaluate the already-bound physical consumer; prepare one complete successor; publish once.

Do not duplicate command execution during native substeps, retries or display frames. The M14.23 preparation cursor advances when its proposal is issued. A later physical refusal does not erase that fact. Keep the genuine engine/resource proposals available for the same outstanding interval where safe. Resource re-preparation may reuse the valid parent; retiring the engine parent does not rewind its interval cursor. Never obtain a fresh proposal for a consumed boundary to rerun propulsion.

Queued future commands do not change the already closed source demand. A source revision/lease change invalidates that prepared interval. Existing pending authoritative timeline event at or before target prevents private stepping and publication. Exact interior fuel exhaustion is an interval-local WOULD-event in the prepared resource proposal, not a synthetic timeline event and not permission to split the BEPU step.

## 3. Mapper owner and lifetime

The mapper is a **pure numerical preparation function invoked by the engine's selected retained-contact consumer**, immediately before native input installation, after genuine source/engine/resource/contact applicability checks. It has no independently retained authority or scheduler. It reads the common prepared facts and produces a small copied native-input value for exactly that interval. Store at most the outstanding interval's provenance/result required for publication retry; do not retain a global projection cache.

Inputs: exact hp/H from banked PropellantDuration/PropellantInteger; proposed body-frame force and COM moment; the checked source frame/orientation transform; current acknowledged source mass and inertia; ordinary full interval H and declared environmental acceleration. Current LocalContactSource owns a captured **constant force**, not a variable-mass gravity model. Do not silently reinterpret it or keep a wet-weight force after canonical mass changes.

The new resource-aware qualification binding therefore owns an explicit immutable **uniform-gravity-acceleration fixture input** in the engine's existing prepared episode configuration: value `(0,-9.81,0)` in the declared local frame, frame/model/version identity and immutable dry-body/resource identity. It is cold prepared/validated against the named numerical fixture and compared on every source admission by identity and value; runtime edits fail closed. Reject a simultaneous nonzero legacy external force/torque law in this new mode rather than double applying or converting it. Apply this acceleration exactly once with the separately prepared engine contribution; do not store an invented propagation force law in the endpoint. Old fixed-force contact mode remains unchanged. This is a required narrow prepared-environment input for the new consumer, not a claim that such gravity ownership is already implemented or a live Earth force model.

For the first bounded scheme, perform the admitted source-frame transform during preparation and hold that ordinary physical input for the interval, matching the accepted fixed-wrench approximation. This is not a universal continuously rotating-engine integrator. The integrated source/body transform must be tested against the admitted contact reference and its existing materiality bars; do not borrow M15.0's broader rotating-wrench promises. An input that cannot stay within the admitted witness/model applicability refuses before native mutation.

Reuse the accepted fixed-workspace expression sequence generated by allocation-recheck/recheck.ps1 from Correction.cs and the banked ratio/scale primitives. Production accepts exact resource values directly; no diagnostic JSON, Fraction/Rational/BigInteger parsing or new rational arithmetic path. Return typed arithmetic/applicability failure, not normal-refusal exceptions from the diagnostic harness.

The established six fixture observables are ax, ay, alpha-x, alpha-y, inverse mass and backend H. Their FP32 bits remain protected for identical admitted operands; absent vector components remain exact zeros in that witness. The off-COM reference bits are [1077935923, -1061557234, -1077097267, 1067030938, 1040187119, 1015580809]. Production vector transport may carry the other transformed components, but that is the same bounded projection responsibility, not evidence those additional cases were already qualified. Test any added composition independently. Do not label four historical discarded double values canonical. Actual committed FP64 pose/velocity/orientation and exact resource units retain their own strict contracts.

The first qualification can bind the already-declared dry8/I2 numerical body and qualification box as an explicit inertial-body model; this is not a new production spacecraft collider or an assertion of homogeneous box density.

Keep original episode T0/SourceEnd, moving-origin epoch, frame, configuration, shape/COM, body handle and world generation. Successful canonical acknowledgement writes only prepared expected properties/resource/pose/revisions/clock/frontier and pending-state fields. **It does not call SetLocalInertia, awaken a body or call BEPU.** That separates irrevocable canonical commit from potentially failing numerical preparation for the next interval.

## 6. Physical/contact versus free-flight boundary

A cold prepared contact episode is contact-owned at source because the engine has explicitly bound a valid retained world, admitted supported source, fixed fixture/frame and genuine acknowledged frontier. The first slice does not discover entry from free flight. Select contact before evaluating any interval; do not run free flight and then decide whether to keep its answer after contact.

Follow the current KSA owner-level pattern for the future: native solved state/support observation can prepare a **next-boundary** regime decision for the same spacecraft. It does not replace spacecraft, command, resource or engine identity. A later accepted departure boundary could use the copied exact committed endpoint as the free-flight source and retire private contact ownership under that same owner. It may not infer an exact continuous departure time from a final contact count or copy KSA's whole situation/horizon/vehicle framework.

For this first slice, do not implement that handoff. Before stepping, admit only the retained supported domain; if a successful solve no longer meets supported-only applicability, return UnsupportedRegime, preserve canonical source/resource, and terminally invalidate the advanced private continuation. Do not fall back to free flight for the same interval or debit fuel from the rejected proposed result. The actual terminal private state is not published as if it were a qualified supported endpoint. No further simulation progresses until explicit cold recovery outside this slice. Later departure qualification can choose to commit a valid separated endpoint and hand off at a boundary; that future behavior is not claimed here. Recontact requires separately prepared entry and a new contact capability, not an automatic cache reuse.

## 8. Failure and retry ledger

Host admission, command commit, private preparation, private solve and canonical physical publication are distinct linearization points. A failed later operation does not erase already accepted host credit or command state.

| Failure | What may already have changed | Canonical authority / retry / invalidation |
|---|---|---|
| Wrong thread/reentrancy/foreign authority | Nothing in this request | Refuse; no lock substitution or automatic rebind. |
| Stale command/engine/resource/source revision or changed definition/rate/frame/mass | Earlier legitimate host/command commits may exist | No physical/fuel commit for this interval. Reject stale leases; terminal episode if source cannot be the same acknowledged authority. No numerically-equal bypass. |
| Invalid mapper arithmetic/input/outside admitted model | Private engine cursor may already be prepared | No native or canonical physical/resource change. Safe same-proposal retry only if input/applicability can legitimately be satisfied; do not rewind or reissue consumed engine edges. |
| Event <=target, insufficient debt, history/revision capacity | No private solve if cheap preflight catches it | Retain canonical debt/source. No event execution here. Safe retry only with unchanged authority and same proposal; external clock changes are not auto-acknowledged. |
| Body removed, foreign generation/receipt, unexpected private writer | Private ownership no longer trustworthy | Canonical source and resources remain authoritative; invalidate continuation. Ordinary native manifold refresh is not this failure. |
| Native property install or Timestep/export failure | Private body may be mutated | No proposed fuel debit; terminally invalidate world/consumer. Prior canonical credit/publications remain. No automatic reconstruction. |
| Unsupported support/departure result | Private step occurred | Supported-only slice refuses publication, no resource debit, invalidates continuation; no same-interval second consumer. |
| Valid pending endpoint, ordinary precommit publication refusal | Exactly one private endpoint staged | Preserve sound receipt/result and all source leases where safe; retry **publication only**, never another propulsion/solver step. Stale source instead invalidates. |
| Proposed resource/actuator/physical successor mismatch | Private step may have occurred | Refuse before canonical writes; mixed/forged proposal is terminal or rejected by seal. Never synthesize a matching resource after the fact. |
| Canonical commit + failed private acknowledgement | Complete canonical bundle committed | Distinct terminal result with copied committed observation; leases dead; no rollback, no debit/publication twice. |
| Host accounting commit + failed acknowledgement | Canonical debt committed | Preserve debt, invalidate continuation, explicit committed terminal status. |

## 9. Time, host and warp

Current source authority is 1,000,000 canonical ticks/s. Ordinary schedule remains T0+floor(n*1,000,000/60): 16,666/16,667 intervals, no reset after publication. The mass investigation kept its original **ordinary 1/60** numerical fixture unchanged. In production the mapper uses **exact H=(targetTicks-sourceTicks)/1,000,000** in hp/H and all weighted products; only the native transport duration uses the existing FP32 projection of that ordinary H. Never use hp or a minimum event dt as a native step. Literal1/60 six-bit replay remains the independent diagnostic mapper contract; neither canonical lattice interval is required to have the literal1/60 backend bits. Validate both lattice lengths with their independently derived exact resource/reference inputs. Do not silently change public time to60 ticks/s or replace exact debt with accumulated float time.

Prepare the event input once per actual serviced physical interval, after selecting its consumer, not once per display frame or per solver iteration. Backlog repeats the same sequence against each newly committed source, at most four intervals per call in the first slice. Service-existing-debt does not resubmit host samples. Rendering occurs once per display frame from the last copied committed endpoint; no through-contact interpolation/extrapolation is certified.

First slice remains fixed 1:1, unpaused, no runtime force/configuration edits. Future warp must use existing exact host-rate/debt semantics and bounded service work; it cannot multiply render work or change native ordinary interval length. No new warp implementation is included. Native KSA horizons are not imported as fuel-event scheduling.

Host credit must have **one** canonical accounting operation and input sequence, not two old admissions. For contact-selected execution, prepare both the coordinator's expected-clock/host-sequence targets and the retained world's expected-clock/host-sequence targets from the same checked clock conversion before writes; recheck both while owning the same phase. Commit canonical debt once, then fixed acknowledgement of both prepared expected targets. Reusing only AdmitPoweredHostTime or only AdmitContactHostTime would leave the other expected clock stale. If either private acknowledgement unexpectedly fails after debt commits, invalidate the whole contact-selected continuation and return committed-accounting/private-invalidated; debt is not rolled back. For free flight the existing single coordinator acknowledgement remains behaviorally unchanged.

## Payoff and remaining risks

Ordinary BEPU retains solving/cache ownership; exact resource/event authority survives without event-sized native work; current engine owns one joint successor; game identity survives future consumer selection. A bounded input/property update is cheaper and more coherent than Candidate-A cache machinery, but no universal speedup is claimed.

Remaining implementation acceptance risks are explicit: concrete central-reservoir admission, source-body/frame projection, both exact lattice lengths, repeated mass refresh/convergence, genuine joint lease integration, tail attribution at real cadence, exact-zero complete-path allocation and retained storage. These are validation obligations, not already-passed results. A newly discovered physical insufficiency returns to Project Control without a new solver/mass policy by assumption.
