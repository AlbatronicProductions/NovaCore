# Current terrain responsibility maps

Read with [the decision and evidence limits](README.md). These are implementation
observations, not measured KSA performance. KSA means the installed build 5402,
not every later commit mentioned in Discord. Exact inspected paths and hashes are
in `source-files.json` and `verification.json`. Member names below are lookup
anchors in those files; no proprietary implementation is reproduced.

Frequency vocabulary: **ONCE** = PREPARED ONCE per asset/library lifetime;
**OCCASIONAL** = UPDATED OCCASIONALLY on authoring/settings/content changes;
**MOVEMENT** = UPDATED ON MOVEMENT, snap or selected level changes;
**FRAME** = PER-FRAME; **DRAW** = PER-DRAW;
**SAMPLE** = PER-FINAL-SAMPLE. A persistent allocation is not a persistent result.

## Persistence inventory and invalidation

| Data/work | KSA classification | NovaCore classification | Consequence |
|---|---|---|---|
| Topology, adjacency, vertex density | PREPARED ONCE | PREPARED ONCE | Already equivalent reusable libraries |
| Refinement factors / final generated vertices | PER-DRAW / PER-FINAL-SAMPLE | PER-DRAW / PER-FINAL-SAMPLE | No discovered KSA cache to adopt |
| Geographic elevation and authored physical modifier results | PER-FRAME render preparation; MOVEMENT collision samples | UPDATED ON MOVEMENT/content for prepared base | NovaCore has existing render reuse advantage |
| Analytic near height/gradient | No equivalent final analytic physical family in KSA TES | PER-FINAL-SAMPLE | The central semantic gap |
| Prepared normals | PER-FRAME adjacency pass | UPDATED ON MOVEMENT/preparation | KSA normals represent its generated base mesh, not an analytic final-detail derivative |
| Basis/anchor | UPDATED ON MOVEMENT; packed per frame | UPDATED ON MOVEMENT; current/incoming frames | KSA local precision representation is transferable in principle |
| Bounds and visibility | PER-FRAME from prepared geometry + displacement maximum | PER-FRAME from persisted physical geometry + envelope | Metadata persistence does not make camera visibility persistent |
| Material phase/address | PER-FRAME CPU phase, PER-FINAL-SAMPLE local lookup | Ordinary inverse already removed; near field PER-FINAL-SAMPLE | Remaining near field contains varying warp/blend; no extra constant term proven |
| GPU physical geometry | Buffers ONCE, contents PER-FRAME | Buffers/results reused until movement/content invalidation | Allocation reuse must not be called geometry caching |
| Source textures, modifier records, residency views | UPDATED OCCASIONALLY; async completion/content version | UPDATED OCCASIONALLY; catalog/record identity and readiness | Neither view readiness nor cache hit alone proves physical equivalence |
| Collision geometry | UPDATED ON MOVEMENT/impact demand; rolling per-vehicle patch | Canonical CPU authority exists; future collision integration not implemented by this ticket | Do not transplant a physics cache as a rendered mesh cache |

KSA's frame stability mechanisms are prebuilt topology, fixed maximum-size
frame-slot buffers, specialized modifier dispatches, asynchronous texture upload,
bounded mip steps, pooled images, and delayed retirement. Its uploader targets
32 MiB batches and 96 MiB in flight; these are scheduling bounds, not a measured
hard frame-time guarantee or proof a single large request cannot overshoot a
batch threshold. Local authored modifiers have resident asset inputs; no separate
streamed geographic decal publication transaction was found.

Terrain compute is called by `Program`'s render command sequence. Simulation
advancement and collision trajectory/patch work have separate owners. This is
source evidence that simulation microsteps do not each execute the terrain draw;
it is not a new high-warp performance measurement. KSA's reported low-flight and
warp improvements in physics cannot be charged as GPU terrain savings.
