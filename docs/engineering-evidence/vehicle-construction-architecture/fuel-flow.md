# Compiled propellant plumbing and exact accounting

ConstructionFuelNetwork compiles once from the shared design. Stores are identified by design instance plus local store, with resource type, exact binary64-derived capacity/initial quantity and enabled state. Rates are exact binary64 values in Q/tick; mixtures use positive integer mass weights. Resource identity is data, never a fuel-name branch.

Only declared local FeedStores are eligible on the consumer's own part. First-hop traversal must use a declared FeedInterface. Reverse directed supply edges and bidirectional structural service edges then visit remote parts, whose eligible species stores share a part-local manifold. A visited consumer cannot expose undeclared local stores through a cycle. This is not an internal pipe simulator. Each store appears once despite multiple paths.

Shortest explicit graph-hop distance defines priority levels. FarthestFirst/NearestFirst chooses a positive enabled level per mixture species; equal-level stores share that species rate. This deliberately adapts KSA's current stage/branch and auxiliary-edge rules to NovaCore's explicit opt-in graph. A detachable edge carries propellant only if both endpoint capabilities and the connection explicitly allow it. A separately declared hose can bridge an otherwise blocked structural service. Graph-proof unavailable edges are cold facts, not physical separation.

The solver resolves each entire mixture before adding its demand. It aggregates all active consumers, advances to the earliest exact store exhaustion, recomputes selection/shares, and continues other supplied consumers. No partial mixture produces nominal activity. Actual powered duration is returned as an exact rational observation; this kernel applies no force and publishes no simulation state.

Unmatched fills require rational Q quantities; see [arithmetic proof](fuel-arithmetic-contract.md). A snapshot stores a common denominator, per-store numerators, cumulative depletion events and compiled network digest. Endpoint exhaustion counts too, so constant commands split at integer ticks produce the same canonical snapshot. Parsing validates size, canonical integer encoding, bounds, no credited inventory and event/empty-store consistency. State is immutable. Stage6 makes a proposal authoritative only through the existing SimulationTransactionEngine's joint fuel/power publication; see runtime-instantiation.md.

Representation admission limits:256 stores,256 consumers,1024 mixture terms total and derived scratch width at most1,000,000bits. Counts and derived widths are checked before large sharing tables. These are explicit generic engine capacity limits, unrelated to DLV counts. No replenishment or positive store credits are admitted in this pure-consumption epoch. Dynamic store switching/refill would require a separately qualified command/lifetime contract; it is not silently performed.

DLV witness is static:36 stores and38 consumers bind through generic facts; cross-stage propellant is absent. This does not admit DLV consumption, its protected residuals/shared helium budget, moving mass or launch dynamics. Non-DLV accounting fixtures supply the active tests.

Qualification:2,075 checks,400 independent reduced-fraction oracle cases, unmatched mixtures, simultaneous/concurrent consumption, balanced and changing shares, missing/disabled species, graph partitions/hoses/cycles, exact save/reload and interval partition equality, extreme binary64 values, and exact matched-SRV quantity/powered-duration projection. Independent correction re-review and execution PASS. One bounded correction separated direction/inlet proofs and cached a full-length zero activity vector for idle/zero-tick calls. Measurements are in performance-stage3.json: active event5520B/op, active no-event3360B/op, warmed idle0B/op. These are pure accounting costs, not full runtime publication costs.
