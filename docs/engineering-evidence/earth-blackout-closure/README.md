## Diagnostic recording contract

The recorder is opt-in through `NOVACORE_CAUSAL_MAPPING`. The native producer writes an 8 MiB preallocated shared-memory ring: 16,384 records of 512 bytes. It does not open, write or flush files, allocate per event, or wait for the observer. A separate process drains into a preallocated 64 MiB rolling journal. Sequence, commit marker and checksum detect missing, torn and corrupt records. Emitted, received and durably flushed cursors are distinct. Loss invalidates a stage.

The observer flushes approximately every 100 ms. It drains redirected console streams without creating another render-thread disk path; the application retains its existing bounded background session log. The retained journal length depends on event rate: about 16–32 seconds in the inspected Earth stages. Old overwritten history is not represented as retained evidence.

Recorded facts include:

- Frame, submitted frame, GPU-completed frame, command submission sequence, command-buffer/fence handles and current phase.
- Body-relative camera position, altitude and forward direction; viewport; body identity; swapchain generation; acquire and present results.
- CPU planetary patch LOD distribution where applicable, and the active NCSM topology level, vertices, triangles, GPU visibility/cull counters, current/incoming generations and ownership.
- Draw and dispatch calls; direct group counts; indirect buffer/offset identity without inventing GPU-generated group counts.
- Buffer/image creation and destruction, memory allocation/free identity and size, working capacities, topology residency, preparation cursors and reuse counters.
- Fence/device/queue wait durations, GPU phase timestamps and pipeline statistics including tessellation invocations.
- Device memory usage/budget when supported; capability records recur within the rolling window.

GPU debug labels surround preparation, cull/compact, uploads, surface/scene and overlay phases. Device-fault capture is enabled where supported, after a returned device-loss error, with at most 64 address and 64 vendor records; vendor binary capture is disabled. Unsupported and incomplete queries are explicit. No returned device loss occurred, so the real device-fault retrieval path was not exercised. A system-wide hang can prevent both processes from recording or flushing the final events.

Primary API references: [device-fault query](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetDeviceFaultInfoEXT.html), [memory-budget extension](https://docs.vulkan.org/refpages/latest/refpages/source/VK_EXT_memory_budget.html).

It launches exactly one child, does not retry or reboot, and stops on fatal Vulkan results, validation errors, diagnostic loss, invalid terrain/overflow, reported memory-budget excess, GPU frames or completed critical operations over 500 ms, unreturned critical operations over 1 second, or missing active renderer progress. CPU startup has a separate 60-second allowance. One graceful close is followed, if necessary, by one termination attempt against that exact child. No system setting is changed.

The latest observer distinguishes fully completed renderer cleanup from an active-renderer stall; application exit after cleanup remains bounded. It records observer loop/flush maxima, the first stop decision timestamp and native stop reason. The native heartbeat deadline remains 1 second.
